# 施設ナレッジの抽出と蓄積

メッセージから「シートを直すための情報」と「シートに無いが対応に役立つ情報」の両方を拾い、毎回同じ形式で書き出して積み上げる。キーワードでの仕分けは参考にとどめ、会話は必ず全部読む。

## 1. 準備（毎回確認する）

- **APIキー**：Beds24 の長期トークン（読み取り専用）。作成時に「Allow linked properties」にチェックし、権限は bookings・bookings-personal・properties を読み取りで付ける。キーはスクラッチパッドにファイルで保存し（`umask 077`）、`--key-file` で渡す。リポジトリには保存しない。
  リフレッシュトークンや招待コードを渡された場合は、交換のたびに新しいキーが発行されるので、手で交換せず `fetch_messages.py` に任せる（新しいキーはキーファイルに上書きされる）。
- **ネットワーク**：`beds24.com` と `api.beds24.com` への接続が許可されていること。
- **施設早見表**：最新版を CSV で書き出したもの（1行目が列名）。版によって列名が違っても動く。
- **前回までのナレッジDB**（`knowledge_db.csv`）：あれば受け取る。無ければ今回が初回。
- **対象と期間**：Beds24 のグループ名・施設名と、期間（指定がなければ30日）。分からなければ `--list-properties` で一覧を出して確認する。

## 2. 手順

1. **取得**
   `python3 fetch_messages.py --key-file KEY --group "グループ名" --days 30 --out OUT`
2. **整理**
   `python3 build_review.py --data OUT --sheet SHEET.csv --company 管理会社名`
   review.md の「0. シートに行がない施設・部屋」を見て、新規施設・新しい部屋を確認する。
3. **通読（省略しない）**
   - `OUT/templates.md` を全部読む。自動送信の中身は、ゲストが実際に受け取っている「公式の案内」。
   - `OUT/conversations_*.md` を全部読む。大きいときは Read の offset と limit で分けて、最後まで読む。
   - 施設の設定（住所・チェックイン/アウト時刻・部屋とユニット・最大人数）は `OUT/raw/properties.json` で確認する。
4. **書き出し**（すべて OUT に作る）
   - `sheet_updates.csv`：既存の列への修正・追記案。列は「施設、対象行、列、区分（修正・追記・空欄補完・要確認・一致）、現在の記載、提案する記載、根拠、要確認」。
   - `new_rows.csv`：シートに行がない施設の新規行。シートと同じ列を同じ順で並べ、分かった列だけ埋める。推測を含む値には「⚠️要確認」を付ける。
   - `knowledge.csv`：シートの列に収まらない情報（4章の基準）。`python3 merge_knowledge.py --template OUT/knowledge.csv` で作ってから行を足す。
5. **チェックと蓄積**
   - `python3 merge_knowledge.py --check OUT/knowledge.csv`
   - 前回のDBがあれば先に読み、同じ項目には既存の ID を「ID」列に書く（更新として扱われる）。新しい項目は ID を空のままにする。
   - `python3 merge_knowledge.py --new OUT/knowledge.csv --db DB/knowledge_db.csv`
     → ID の採番、根拠の重複除去、件数、初出・最終確認日、更新履歴の記録は自動で行われる。変更点は `knowledge_db_changes.md` に出る。
6. **レポート**：`report.md` にまとめる（最重要ポイント、シートの修正案の要約、新規施設、リスク）。
7. **渡す**：`report.md`・`sheet_updates.csv`・`new_rows.csv`・`knowledge_db.csv`・`knowledge_db_changes.md` を SendUserFile で送る。データは公開リポジトリにコミットしない。

## 3. 書き出す先の振り分け

- シートの既存の列に入る内容 → `sheet_updates.csv`（新規施設なら `new_rows.csv`）
- シートの列に収まらない内容、または列に入れるには細かすぎる内容（手順・前例・言い回しなど） → `knowledge.csv`
- どちらにも当てはまる重要な手順（お湯が出ない時の対処など）は両方に書いてよい。knowledge には「シート反映」に列名を書く。

## 4. knowledge.csv に書くもの

次のどれかに当てはまれば書く。シートに列があるかどうかは関係ない。

1. **Q&A**：今後また聞かれそうな質問とその答え。2回以上聞かれたもの、または答えを知らないと返信が遅れるもの。
2. **施設情報**：シートの列に収まらない事実。設備や備品の場所、部屋の構造、建物の特徴、置いていない物など。
3. **手順**：トラブルの対処（お湯・ガス・電気・Wi-Fi・鍵・家電・洗濯機など）。ゲストに伝えた手順、原因、スタッフを派遣する条件まで書く。
4. **料金・ルール・期限**：実際に案内した金額・期限・条件。施設によって違う場合はそれも書く。
5. **前例**：特別対応（返金、無料延長、例外の受け入れ）。誰が判断したかが分かれば書く。
6. **注意点**：苦情、誤解、トラブルになりかけた対応、レビューで指摘されたこと、返信漏れ。予防策も書く。
7. **食い違い**：シート／自動メッセージ／スタッフの回答／Beds24 の設定／掲載ページのあいだで内容が違うもの。
8. **改善**：案内文・掲載情報の不備。古い情報、誤字、別の施設の文面が送られている、など。
9. **良い言い回し**：不安なゲストへの説明など、そのまま使える返信は「返信文案」に書く。

書かないもの：

- ゲストの個人情報（氏名、メールアドレス、電話番号、住所、パスポート番号、個人的な事情の詳細）
- 挨拶やお礼だけのやり取り
- 1回きりで今後の対応に役立たない雑談

## 5. 列の書き方

| 列 | 書き方 |
|---|---|
| ID | 新規は空。前回DBの項目を更新するときはその ID |
| 施設 | Beds24 の施設名。グループ全体に当てはまるものは「共通」 |
| 部屋 | 特定の部屋だけに当てはまるときの部屋番号 |
| 分類 | 入室・鍵／本人確認・名簿／入国手続き／予約・人数変更／料金・支払い／キャンセル・返金／チェックイン・アウト／荷物／設備・使い方／トラブル対応／清掃・備品／寝具／ゴミ／騒音・近隣／喫煙／周辺・観光／交通・アクセス／連絡手段／安全・防災／部屋・掲載情報／定型文・案内文／その他 |
| 種類 | 施設情報／Q&A／手順／前例／注意点／改善 |
| 項目 | 短い見出し（例：パスポートの提出期限） |
| 内容 | 事実・ルール・手順を具体的に書く（金額・時間・場所・条件）。Q&A は「Q: … A: …」の形 |
| 返信文案 | ゲストにそのまま送れる日本語の文案（任意）。シートの返信文と同じ丁寧さで書く |
| 状態 | 確定（自動メッセージ・Beds24 の設定・2件以上で一致）／1件のみ／回答が割れている／要オーナー確認（料金・返金・例外・食い違い） |
| 重要度 | 高（入室・安全・お金・苦情に関わるもの、よく聞かれるもの）／中／低 |
| シート反映 | 入れるべき既存の列名、または「新規列候補: ○○」「特記事項」「FAQ」「反映不要」 |
| 件数 | 空でよい（根拠に書いた予約IDの数を自動で数える） |
| 根拠 | 予約IDと日付（例：#90102934（8/31）、#87535496（9/21））。自動メッセージなら「定型文T5（61回）」 |
| 初出・最終確認 | 空でよい（取り込んだ日が入る） |
| 備考 | 補足。更新履歴は自動で追記される |

## 6. 新規施設（シートに行がない施設）のとき

- `new_rows.csv` にシートと同じ列で下書きを作る。分からない列は空にする。
- Beds24 の施設設定も見る。仮の値（例：住所が「東京1-1-1」）があれば指摘する。
- その施設の knowledge も同じ基準で書く。開業直後は問い合わせが多いので、重要度は広めに判断する。

## 7. 安全とプライバシー

- 暗証番号と Wi-Fi のパスワードは、`sheet_updates.csv`・`new_rows.csv` の該当する列（鍵・Wi-Fi）にだけ書く。knowledge・レポート・チャットには書かない。
- 出力はすべて社内用。リポジトリが公開なので、`out/`・CSV・DB はコミットしない。
- スタッフの回答が正しいとは限らない。食い違いや料金・返金に関わるものは「要オーナー確認」にする。
